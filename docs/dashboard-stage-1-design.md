# Dashboard stage 1 — approved design

The user approved this design on 2026-09-27, after the design check required by [backlog.md](backlog.md#stages). It is implemented in the working tree after the documentation and parser cleanup. Release build, offline checks and SDK framing/loading under .NET Framework passed. The user later reported starting the new build and seeing the event request in the browser; no new native TIA validation was performed. Current MCP tool contracts remain unchanged.

- Reference the existing `Hypermedia.Datastar` 0.1.0 package from both projects, with `packages/` and NuGet.org as explicit package sources. Check that the DLL is copied to the .NET Framework 4.8 output and loads without changing Siemens assembly resolution.
- Add `GET /api/dashboard/events` inside the existing host. Require `X-Tia-Dashboard: 1` and the existing loopback origin policy. Allow at most eight streams; reject an additional stream with HTTP 429 before opening it.
- Use the SDK for SSE headers and framing. Send the current managed dashboard snapshot as Datastar signals, changed snapshots as they arrive, and a heartbeat comment every 15 seconds. Serialize each stream's sends and coalesce pending snapshots so a slow browser cannot block the STA worker.
- The current page opens the stream with `fetch` so it can send the required header. It drains the stream and keeps its existing polling and rendering in this stage. It aborts the stream when hidden or on `pagehide`; visibility and `pageshow` resume it, and unexpected transport failure retries with a one- to thirty-second backoff. A browser stream retry opens a fresh generator; it never reconnects a TIA attachment. An idle disconnect is detected by the next send or heartbeat before the server releases the subscription.
- Monitoring acquires a service-owned subscription for each open stream. Discover and validate connections every two seconds while at least one subscription exists; skip native monitoring when none exist. Core services remain independent of dashboard/SSE types. Verify the subscription again on the STA worker before queued monitoring executes.
- Keep explicit `get_status(processId)` guarded on demand. A closed or replaced native context must not be reported as connected merely because no dashboard stream is open. No attachment is created or reconnected by a status read.
- Remove the browser's manual monitoring pause control when stream lifetime owns background monitoring. Connections, disconnections and Open project remain explicit user actions.

Checks: SDK framing through in-memory streams; admission limit; ordered sends; cancellation/disconnect cleanup; monitoring with zero/one/multiple subscribers; on-demand status after native-context loss; existing dashboard behavior; Release build, offline harness and Node checks. These checks do not establish new native TIA evidence. The managed server is reloaded only on the user's request.

Tool execution routes, server run history, the Datastar-rendered page and schema-based form changes remain their later agreed stages. Bundle the specified client JavaScript when introducing that page.
