## Implemented

- The active page loads only the pinned local Datastar v1.0.4 bundle and CSS. `dashboard.js` and its asset route were removed. The page declares local tab, mode, tool, inspector and field signals; visible controls use Datastar attributes and direct actions. It has no hidden proxy buttons or browser polling for status, logs or history. Event and history GET actions exclude form signals from the query, including source document contents.
- The server patches ID-addressed tab, context, form, run-inspector, activity and log fragments over SSE. Forms come from the published MCP input schemas with server-scoped inventory suggestions. Block and UDT source editors bind native multiline name/content fields; Load selected source copies exact returned content and format into those signals. While that read is in flight, a Datastar indicator freezes the complete draft, source selector and write submit, preventing edits from racing with the returned source. The server owns connection state, selectors, captures and history.
- A visible tool form posts its tab, context stamp, request UUID, tool name and bound fields. Admission checks the displayed runtime/project/connection context, supplies the selected process ID, and fences project calls to the admitted attachment identity. A stale form cannot target a replacement attachment. A dashboard write has no automatic retry. After an admitted write, guarded inventory/detail readbacks start when the required CPU or parent-table context is known; missing context or readback failure is reported. Admitted work and its follow-up reads continue even if the POST stream disconnects.
- Connect and Disconnect send the displayed runtime start identity as a decimal string and project path; Disconnect also sends the attachment ID. The server checks fresh discovery or the retained slot before acting. A stale process card cannot attach to a replacement runtime or detach another connection. These actions still require explicit user intent and never reconnect automatically.
